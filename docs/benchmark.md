## Performance benchmark
```
cd backend && python -m scripts.benchmark --calls 200    # -> reports/benchmark_report.json
```
In-process, 200 calls per series, representative mix (allow / ACL-deny / schema-deny / forbidden-tool):

| Series | p50 (ms) | p95 (ms) | What it measures |
|---|---|---|---|
| **Policy decision** (incl. advisory risk, excl. audit write) | **1.64** | **3.47** | the deterministic allow/deny/approval decision — the enforcement cost |
| **Advisory risk** (ML + heuristics, standalone) | 1.38 | 2.03 | optional detector latency, measured separately (a component of the above, not additive) |
| **End-to-end** (incl. durable tamper-evident audit write) | 35.79 | 36.30 | wall time; dominated by SQLite fsync on this laptop, a persistence cost not a policy cost |

**Reading:** the enforcement decision itself is ~1.6 ms p50. The ~36 ms end-to-end floor is the synchronous,
durable audit write (fsync); production would use WAL group-commit or stream events to an append-only log
service. The optional ML detector adds ~1.4 ms and is never on the critical authorization path.

## Advisory ML classifier (synthetic, leakage-free holdout)
```
cd backend && python -m scripts.train_model   # -> ml_artifacts/metrics.json + dataset.jsonl
```
- Dataset: 559 synthetic samples (EN / Urdu / Roman-Urdu / base64 / zero-width strata), deduplicated.
- Split: **group-aware** (template variants never cross) → train 403 / holdout 156, `leakage.ok = true`,
  identical-texts-in-both-splits = 0.
- Holdout (disjoint templates): confusion `{tn:41, fp:0, fn:0, tp:115}` → precision 1.0, recall 1.0,
  FPR 0.0, F1 1.0.

> **Honesty note.** A perfect holdout score reflects the *templated separability of synthetic data*, not a
> real-world detection guarantee. The classifier is **advisory only**; the gateway's allow/deny decisions
> are deterministic and do not use it. See `docs/limitations_and_roadmap.md`.
